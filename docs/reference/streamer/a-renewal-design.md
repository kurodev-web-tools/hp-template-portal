# Streamer A Renewal Design

## Scope
- 対象:
  - `public/templates/streamer/a`
- テンプレート名:
  - `Neon Abyss`
- この文書は `streamer/a` renewal の詳細設計をまとめる
- カテゴリ全体方針は `STREAMER_RENEWAL_PLAN.md` を参照する

## Renewal Goal
- `streamer` カテゴリ内で、`a` を「ネオン装飾が強いテンプレート」から「深度のある没入体験を持つテンプレート」へ格上げする
- 表現品質を上げつつ、HP として必要な情報を失わない
- Vtuber / streamer の活動拠点として、世界観訴求と活動整理を両立する

## Core Experience
- 中心体験:
  - `depth-scroll`
- ユーザーの体感:
  - 下へ読むのではなく、奥へ潜っていく
- 構造:
  - 各層がほぼ 1 画面ずつ現れる潜航型
  - ただし層の切り替わりは連続的で滑らかに接続する
- 主役になる印象:
  - 仮想海 / データ深海へ潜航しながら、配信者の存在設定と活動を順に解放していく

## World Direction
- 世界観の核:
  - `仮想海 / データ深海`
- キーワード:
  - 発光粒子
  - 深度
  - 沈降
  - 生体発光
  - 潜航ログ
- やらないこと:
  - サイバーパンク記号の足し算に寄せすぎない
  - 常時激しいグリッチや過剰な HUD で読みにくくしない
  - 「ネオン都市」や「宇宙航行」に寄せて `n` / `o` と競合しない

## Information Priority
- 1. 世界観紹介
- 2. キャラクター設定
- 3. 活動プロフィール
- 4. 配信スケジュール
- 5. アーカイブ / ハイライト
- 6. CTA / SNS / コミュニティ

## Section Structure

### 1. 潜航ヒーロー
- 役割:
  - 第一印象で深度体験を成立させる
- 見せるもの:
  - キャラクターの近景
  - 仮想海の深度空間
  - 軽い CTA
  - LIVE 状態やチャンネル導線の存在
- スクロール時の変化:
  - 顔寄りから腰上へ遷移し、奥の層が見え始める

### 2. 世界観 / 存在設定
- 役割:
  - 何者かを先に掴ませる
- 見せるもの:
  - 存在名
  - 所属や肩書き
  - 世界観テキスト
  - 活動の前提となる存在設定
- 方向性:
  - 活動ジャンル説明より先に、キャラクター文脈を見せる

### 3. 活動プロフィール
- 役割:
  - 何を配信しているかを整理する
- 見せるもの:
  - 主配信ジャンル
  - 得意企画
  - 活動時間帯
  - コラボ傾向や特徴
- 方向性:
  - 世界観を壊さず、活動実態が読める UI にする

### 4. 配信スケジュール
- 役割:
  - 直近の参加判断に必要な情報を出す
- 見せるもの:
  - 次回配信
  - 今週の配信予定
  - 特集テーマ
- UI 方針:
  - 単なる表ではなく、世界観化したログ UI として見せる
  - 将来的に通常の日時表記へ戻しやすい構造にする

### 5. アーカイブ / ハイライト
- 役割:
  - 初見ユーザーの入口を作る
- 見せるもの:
  - アーカイブ代表回
  - 切り抜き / 見どころ
  - 代表的な配信テーマ
- 方向性:
  - サムネイル一覧ではなく、深海内の観測ログや記録片のように見せる

### 6. CTA / SNS / コミュニティ
- 役割:
  - 参加導線を明確にする
- 見せるもの:
  - チャンネル移動
  - 通知 / follow
  - X
  - YouTube
  - Discord
  - 必要に応じて TikTok 等
- 方向性:
  - 押せることは最初から分かる
  - ただし広告バナー風ではなく、世界観に溶けた HUD として存在させる

## Character Stage
- キャラクターは `character stage` で受ける
- 想定素材:
  - 静止画
  - 背景透過動画
  - 将来のレイヤー分割素材
- 初期実装の前提:
  - 静止画だけでも成立する
- 将来拡張:
  - 軽い呼吸
  - 髪や発光の微揺れ
  - 視差による微小反応

## Character Transition
- 変化軸:
  - `距離`
  - `光環境`
- 基本遷移:
  - `顔寄り → 腰上 → 空間込み`
- 実装前提:
  - 高度な 3D 変形を必須にしない
  - 複数画像または動画レイヤーのフェード切り替えで成立させる
- 補足:
  - 顧客によって逆順や固定構図に差し替えやすい構造にする

## Motion And Effects
- 主役演出:
  - 深度変化
  - 発光粒子の距離感
  - 光環境の変化
- 補助演出:
  - レイヤーごとの速度差
  - UI の穏やかなフェード
  - 情報レイヤーの解放
- 避けること:
  - 常時強いグリッチ
  - 派手なノイズ多用
  - ポストエフェクト依存で可読性を落とすこと

## CTA Strategy
- CTA は初期表示から見せる
- ただし強い固定ボタンではなく、軽い HUD 導線として置く
- 想定導線:
  - 配信中インジケータ
  - チャンネル移動
  - 通知 / follow
  - SNS
- 深く潜るほど CTA は具体化する
  - アーカイブ
  - コミュニティ参加
  - 問い合わせやコラボ導線

## Technical Direction
- 背景深度と粒子:
  - `three.js`
- セクション遷移と制御:
  - 通常の JS + CSS
- キャラ切り替え:
  - 画像 / 動画レイヤーの切り替え
- 基本方針:
  - `WebGL` は「3D を見せるため」ではなく、「潜航感と奥行き反応を返すため」に使う
- 非採用:
  - 重いポストエフェクトの常用
  - Live2D モデルそのものの直接運用前提

## Non-Goals
- 企業 HP 的な軽量最優先設計にはしない
- 配信接続やチャンネル接続の状態遷移を主役にしない
- ネオン演出を増やすだけの superficial refresh にしない
- 1 画面固定の実験アート作品に寄せすぎない

## Why This Direction
- `streamer` は第一印象のインパクトが重要で、高演出路線と相性が良い
- 一方で HP として、活動内容、スケジュール、各種導線は失えない
- そのため `a` は「世界観没入」と「活動整理」のハイブリッドにする
- `depth-scroll` を軸にすれば、モバイルでも体験を保ちやすい

## Comparison To Other Streamer Templates
- `n` と被らない点:
  - `n` は深夜覚醒感、`a` は深海潜航感を主役にする
- `o` と被らない点:
  - `o` は軌道や宇宙移動、`a` は水圧と沈降の感覚を主役にする
- `f` / `t` と被らない点:
  - `a` は起動やコマンドではなく、空間深度の体験を中心にする

## Implementation Notes
- 1 viewport ごとに主役情報を切り替える構成を保つ
- ただしセクション境界は硬くしすぎず、演出で連続接続する
- モバイルでのスクロール感を最優先で調整する
- character stage は素材差し替えに強い構造へする
- 顧客案件ではキャラクター素材未確定でも成立するよう、空間だけ先に完成できる設計にする

## Open Knobs
- キャラ素材が静止画か透過動画か
- キャラ遷移の順番を逆転するか
- スケジュール UI をどこまで抽象化するか
- SNS 導線の数と優先順位

## Readiness Check
- renewal の狙いが明確
- 中心体験が明確
- 情報優先順位が明確
- キャラクター見せ方が明確
- CTA と schedule の扱いが明確
- 技術方針が明確
- 非採用案が明確

現時点で、別セッションで `streamer/a` renewal 用 worktree を切って実装へ入れる粒度としては十分。
