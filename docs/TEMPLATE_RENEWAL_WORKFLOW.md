# Template Renewal Workflow Starter

この文書は、テンプレート renewal を始めるときの依頼方針とタスク分解の共通ルールをまとめたものです。  
依頼文そのものはここに固定せず、テンプレート名と参照パスを毎回差し替えて使います。

## Standard Flow

1. 対象テンプレートの設計書や入力資料を確認する
2. `task.md` の有無を確認し、空なら初期化する
3. 実装タスクを小さく分ける
4. Phase 1 は骨組みだけを作る
5. 1タスクごとに確認してから進める
6. 1タスクごとにコミットする
7. 完了後に `safe.directory` を整え、ユーザーが `push` / `PR` を行う

## Suggested Task Split

- Phase 1: 骨組みのみ
  - セクション順
  - カラム構成
  - 固定要素の配置
  - 演出やアニメーションは入れない
  - `three.js` / `WebGL` / 粒子 / 泡の置き場だけ必要なら確保する
- Phase 2: 内容投入
  - 見出し
  - 本文
  - CTA
  - 画像
  - 実サイト寄りのコピーを整える
  - ダミー素材や人物情報を差し込む
- Phase 3: 動き追加
  - フェード
  - スクロール連動
  - テンプレート固有の視覚効果
  - 以下のような演出要素
    - 粒子
    - 泡
    - 3D
    - canvas
  - `three.js` / `WebGL` はここで本体を実装する
- Phase 4: モバイル最適化
  - 余白
  - 改行
  - 縦積み
  - メニュー挙動
  - PC 演出の単純縮小ではなく、モバイル向けに見せ方を調整する
- Phase 5: 仕上げ
  - 可読性
  - 破綻
  - 重さ
  - 細部調整
  - 文言の最終調整
  - サムネイルや補助資産の確認
  - 設計書や `task.md` の追従更新

## Notes

- `task.md` は直近作業の正本
- `docs/AI_WORKFLOW.md` は運用ルールの正本
- 対象テンプレートの renewal design doc は、実装判断の正本として毎回明示する
- 依頼時の具体文は、この文書を参考にしつつテンプレート名と対象パスを差し替えて使う
